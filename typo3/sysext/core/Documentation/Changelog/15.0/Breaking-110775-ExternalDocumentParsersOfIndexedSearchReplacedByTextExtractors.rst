===========================================================================================
Breaking: #110775 - External document parsers of indexed_search replaced by text extractors
===========================================================================================

See :issue:`110775`

Description
===========

The system extension :composer:`typo3/cms-indexed-search` extracted the text
of linked documents such as PDF or Word files with "external parsers". These
duck-typed classes were registered in
:php:`$GLOBALS['TYPO3_CONF_VARS']['EXTCONF']['indexed_search']['external_parsers']`
and were bound to the indexer through a back-reference.

The external parsers are replaced by text extractors, which are registered
as tagged services and used through the
:php:`\TYPO3\CMS\Core\Resource\TextExtraction\TextExtractorRegistry`, see
:ref:`feature-110775-1790261961`. This comes with the following breaking
changes:

-   The array
    :php:`$GLOBALS['TYPO3_CONF_VARS']['EXTCONF']['indexed_search']['external_parsers']`
    is not evaluated anymore. The class
    :php:`\TYPO3\CMS\IndexedSearch\FileContentParser` has been removed. Its
    work is done by text extractors in the namespace
    :php:`\TYPO3\CMS\IndexedSearch\TextExtraction`.

-   Only files that are part of a File Abstraction Layer (FAL) storage are
    indexed. The indexer does not index external URLs anymore, and the
    extension setting :php:`indexExternalURLs` has been removed. Files are
    resolved from links to public files of a storage, and from file dump URLs
    of non-public storages. Links using :php:`jumpurl`, as well as links to
    files outside of a storage, including absolute file system paths, are
    not followed anymore. The indexer now handles every linked document as a
    FAL file: the extractor is selected by the MIME type stored in the FAL
    index, time and size are read from it, and access to files of non-public
    storages is checked by the token of the file dump URL. Documents fetched
    from a URL or read from an arbitrary path have no such record and would
    need a second indexing path next to FAL, with its own HTTP client and
    temporary files. JumpURLs are not generated by TYPO3 Core since TYPO3 v7.5.

-   The modification time, creation time and size of an indexed file are
    read from the FAL index instead of from the file system.

-   The text extractor of a file is selected by the MIME type stored in the
    FAL index, instead of by the file extension. A generic MIME type, such as
    :php:`application/zip` for a Word document, is mapped to the concrete type
    by the file extension through
    :php:`$GLOBALS['TYPO3_CONF_VARS']['SYS']['FileInfo']['mimeTypeCompatibility']`.
    Office documents detected as ZIP archives or OLE compound files are
    covered by the default configuration. Files stored with a MIME type that
    is not mapped, such as :php:`application/octet-stream`, are not indexed.

-   The following members of
    :php:`\TYPO3\CMS\IndexedSearch\Indexer` have been removed:
    :php:`$external_parsers`, :php:`$indexExternalUrl_content`,
    :php:`initializeExternalParsers()`, :php:`indexExternalUrl()`,
    :php:`getUrlHeaders()`, :php:`readFileContent()` and
    :php:`fileContentParts()`.

-   :php:`Indexer->indexRegularDocument()` has been replaced by
    :php:`Indexer->indexFileDocument(FileInterface $file, string $fileUrl, bool $force = false)`.
    The array returned by :php:`Indexer->extractHyperLinks()` does not
    contain the key :php:`localPath` anymore, links are resolved to files by
    :php:`Indexer->extractLinks()`.

-   The constructors of :php:`Indexer`, :php:`SearchController`,
    :php:`IndexSearchRepository` and :php:`AdministrationRepository`
    changed. :php:`IndexSearchRepository->initialize()` does not accept the
    external parsers anymore, and :php:`AdministrationRepository->external_parsers`
    has been removed.

-   Text of HTML based documents, such as HTML files, is now always split
    into title, meta keywords, meta description and body. The setting
    :php:`config.index_metatags` does not apply to the content of files.
    Title, keywords and description of a document are consistently taken
    from the extractor. A file name is only used as the title if the
    extractor does not return one.

Impact
======

Custom external parsers registered in
:php:`$GLOBALS['TYPO3_CONF_VARS']['EXTCONF']['indexed_search']['external_parsers']`
are not called anymore. Documents of the file types they handled are not
indexed anymore, until a text extractor is registered.

Extensions calling or extending the removed methods of the indexer, or
relying on the removed classes and properties, will fail with a PHP error.

External URLs and files outside of a FAL storage are not added to the search
index anymore. Entries of such documents that already exist in the index are
not updated anymore.

Files whose stored MIME type is neither supported by an extractor nor mapped
by :php:`mimeTypeCompatibility` are skipped. The time tracker log of the
indexed page lists them with the message "No text extractor found" and their
MIME type. This also affects documents of OpenOffice.org 1.x (:file:`sxc`,
:file:`sxi`, :file:`sxw`) that older versions of :file:`libmagic` detected
as :php:`application/zip`, which is only mapped for the current Office Open
XML and OpenDocument formats.

An extractor whose external tool is not configured or not found does not
support any MIME type, so its file types are neither indexed nor offered in
the search form. This is logged once per request or console command with
the log level "notice", naming the extractor, its MIME types and the
missing tools.

Affected installations
======================

Installations with custom external parsers for the indexed search, with an
extension that interacts with the :php:`Indexer` to index files or URLs, or
that enabled the extension setting :php:`indexExternalURLs`. The extension
scanner reports usages of the removed API.

Migration
=========

Remove the registration of the parser from :file:`ext_localconf.php` and
implement a text extractor instead, registered with the attribute
:php:`#[AsTextExtractor]`. The extractor receives the file as a system resource,
so the content can be read with :php:`getContents()`:

..  code-block:: diff
    :caption: EXT:my_extension/ext_localconf.php

    -$GLOBALS['TYPO3_CONF_VARS']['EXTCONF']['indexed_search']['external_parsers']['dwg'] = MyDwgParser::class;

..  code-block:: php
    :caption: EXT:my_extension/Classes/TextExtraction/DwgTextExtractor.php

    use TYPO3\CMS\Core\Attribute\AsTextExtractor;
    use TYPO3\CMS\Core\Resource\TextExtraction\ExtractedText;
    use TYPO3\CMS\Core\Resource\TextExtraction\StructuredTextExtractorInterface;
    use TYPO3\CMS\Core\SystemResource\Type\SystemResourceInterface;

    #[AsTextExtractor]
    final class DwgTextExtractor implements StructuredTextExtractorInterface
    {
        public function getSupportedMimeTypes(): array
        {
            return ['image/vnd.dwg'];
        }

        public function extractStructuredText(SystemResourceInterface $resource): ExtractedText
        {
            // Read $resource->getContents() and return the text
            return new ExtractedText($text, $title);
        }
    }

Files are now selected by their MIME type instead of their file extension. The
file extensions of a MIME type are indexed as soon as the extractor declares
the MIME type in :php:`getSupportedMimeTypes()`. A link to a public file is
only resolved through FAL if its file extension is one of these, so other
linked files are not added to the FAL index. File extensions that must not
be indexed can still be listed in the extension setting
:php:`ignoreExtensions`.

The label of a file type in the media type selector of the search form, which
the method :php:`searchTypeMediaTitle()` of a parser provided before, is the
label :php:`mediaTypes.<file extension>` of the plugin. A file type without a
label is not offered in the selector. Add it with TypoScript, for example:

..  code-block:: typoscript
    :caption: EXT:my_extension/Configuration/Sets/MySet/setup.typoscript

    plugin.tx_indexedsearch._LOCAL_LANG.default.mediaTypes.dwg = AutoCAD drawings

An exception thrown while a file is indexed, for example by an extractor or by
the driver of a remote storage, is logged and the file is skipped, the page
and other linked files are indexed nevertheless.

If documents are skipped because the file information of the server stores
them with a generic MIME type, check the column :sql:`mime_type` of the table
:sql:`sys_file`. Fix the MIME type detection of the server, for example by
updating the :file:`libmagic` database used by the PHP extension
:php:`fileinfo`, then correct the stored MIME type of the affected files in
the FAL index and let the site be indexed again.

Do not map generic MIME types such as :php:`application/octet-stream` through
:php:`$GLOBALS['TYPO3_CONF_VARS']['SYS']['FileInfo']['mimeTypeCompatibility']`
to make such files indexable. The setting is also applied when the MIME type
of an uploaded file is detected and in the consistency check of file
extension and MIME type of uploads, so such a mapping weakens the validation
of uploaded files.

Documents that were indexed through a URL, or that are stored outside of a FAL
storage, have to be moved into a storage to be indexed. Use the
:php:`Indexer->indexFileDocument()` method instead of
:php:`Indexer->indexRegularDocument()` when indexing a file from PHP.

Index entries of such documents that already exist stay searchable until they
are removed. Delete them in the backend module :guilabel:`Indexing`, in the
view :guilabel:`Detailed statistics`, which lists the documents indexed for
each page. To remove all of them at once, empty the tables
:sql:`index_phash`, :sql:`index_fulltext`, :sql:`index_rel`,
:sql:`index_section`, :sql:`index_grlist` and :sql:`index_words`, and let the
site be indexed again.
